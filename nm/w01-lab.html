Что вы делаете и зачем

В § 1.8 лекции сформулирована оценка Уилкинсона: относительная ошибка наивной суммы \(n\) слагаемых одного знака может доходить до \(nu\) вместо \(u\). При \(n = 10^{5}\) это \(\sim 10^{-11}\) — четыре-пять из 16 значащих цифр, обещанных double, потеряны. Возникает вопрос: существует ли алгоритм суммирования, сохраняющий полную машинную точность при любом \(n\)?

Ответ утвердительный. Задача этой лабораторной — реализовать в C++11 четыре алгоритма:

  1. Наивный (последовательный цикл слева направо) — рабочая лошадка, чью ошибку мы будем побеждать;
  2. Компенсированный Кэхэна (1965) — суммирование с компенсирующей переменной, восстанавливающей потерянные младшие разряды;
  3. Попарный (тот же, что применяет NumPy в np.sum) — рекурсивная свёртка с ошибкой \(O(u \log_2 n)\);
  4. Отсортированный — сумма после сортировки по возрастанию модуля.

Для каждого алгоритма вы измерите относительную ошибку на серии \(n = 10^2 \ldots 10^5\); страница сама построит график в двойных логарифмических осях и покажет на нём границу Уилкинсона \(nu\) и уровень \(u\). Так оценки из таблицы § 1.8 лекции превращаются в наклоны прямых, которые можно измерить.

Вторая часть (§ 7) — про другой источник потерь, катастрофу вычитания из § 1.7: корни квадратного уравнения, \((1-\cos x)/x^2\) и \(\sqrt{a^2+b^2}\) при переполнении. Там лечит не более точная арифметика, а переписывание формулы, и вы увидите, как невязка выдаёт обратную ошибку алгоритма.

Каждая задача — блок с редактором C++ и кнопкой «▶ Запустить». Код компилируется настоящим clang++, собранным в WebAssembly, и исполняется в браузере. Автопроверка — по выводу программы: harness вокруг вашего кода печатает ответы в виде __ANS__число, JS их вылавливает и сравнивает с эталоном.

Ограничение производительности. Интерпретация wasm в браузере в 5–10 раз медленнее нативной. Массивы больше \(n = 10^{6}\) практически не собрать (~8 МБ на массив double, плюс long-running loop). Все задачи здесь используют \(n \le 10^{5}\) — этого достаточно, чтобы увидеть теоретические скейлинги.

Что можно и что нельзя

  • Можно: <cstdio>, <cmath>, <cstdlib> (для qsort), union для бит-разбора double.
  • Нельзя: сторонние библиотеки (Eigen, Boost, fmt); <vector>, <algorithm>, std::sort в браузерном clang.js работают ненадёжно — используйте C-массивы и qsort. И, конечно, готовые суммирующие функции типа std::accumulate.
  • Автопроверка ищет в выводе строки __ANS__число. Всё, что вы печатаете рядом (диагностика, промежуточные результаты) — на вашей стороне.

§2. Компенсированное суммирование Кэхэна

При добавлении маленького \(x_k\) к большому \(s\) младшие биты \(x_k\) теряются в округлении. Компенсированный алгоритм отслеживает эти потерянные биты в дополнительной переменной \(c\) и вычитает их из следующего слагаемого. В итоге ошибка суммы ограничена \(\approx 2u\sum|x_k|\) независимо от \(n\) — как если бы сумма считалась в удвоенной точности, хотя все переменные остаются обычными double.
Задача 2.1. Реализовать sum_kahan. Проверьте, что для того же массива \([0{,}1]\times 10^{5}\) сумма Кэхэна практически равна 10000, а ошибка на порядки меньше наивной.

§3. Попарное суммирование

Идея: сумма пополам делится на две подсуммы, каждая суммируется рекурсивно, потом складывается. Дерево рекурсии имеет глубину \(\log_2 n\), ошибка в худшем случае ограничена \(u \log_2 n \cdot \sum|x_k|\).

§4. Отсортированное суммирование

Ещё одна классическая идея: отсортировать слагаемые по возрастанию модуля и суммировать в этом порядке. Тогда каждая частичная сумма относительно велика по сравнению с прибавляемым слагаемым, и вклад «мелочи» в общий итог не теряется в округлении. Особенно заметно на массивах смешанных знаков.

Задача 4.1. Ряд Лейбница. Реализуйте sum_sorted_abs: сначала сортировка по возрастанию \(|x_k|\), потом наивное суммирование. Проверьте на первых 50000 членах ряда \(\sum_{k=1}^{50000} (-1)^{k+1}/k\), эталон \(\to \ln 2 \approx 0{,}693147\).

§7. Катастрофа вычитания: переписать формулу

Суммирование теряло точность медленно, по \(u\) за операцию. Вычитание близких чисел теряет её мгновенно: по (1.8) относительная ошибка разности усиливается в \((|a|+|b|)/|a-b|\) раз. Ни Кэхэн, ни попарная сумма тут не помогут — лечится только переписывание формулы так, чтобы опасного вычитания не было. Три классических случая из § 1.7 лекции.

Задача 7.1. Корни квадратного уравнения по Виета. Для \(x^2 + bx + c = 0\) при \(b = 10^8\), \(c = 1\) корни \(x_1 \approx -10^8\) и \(x_2 \approx -10^{-8}\). Школьная формула \(x_2 = (-b + \sqrt{b^2 - 4c})/2\) вычитает два числа, совпадающих в 16 знаках. Реализуйте roots_stable: сначала больший по модулю корень \(x_1 = -\bigl(b + \operatorname{sign}(b)\sqrt{D}\bigr)/2\) — там сложение, — затем \(x_2 = c/x_1\) по теореме Виета. Harness сравнит с наивной формулой и напечатает невязку \(x^2 + bx + c\) для обоих ответов. Ответ автопроверки — устойчивый \(x_2\).
task7_1.cpp
Задача 7.2. \((1 - \cos x)/x^2\) при малых \(x\). Точное значение стремится к \(1/2\). Наивная формула при \(x = 10^{-8}\) даёт ровно 0: \(\cos x\) округляется к 1, и вычитание не оставляет ни одной верной цифры. Реализуйте f_stable по формуле половинного угла \(\dfrac{1-\cos x}{x^2} = \dfrac{1}{2}\left(\dfrac{\sin(x/2)}{x/2}\right)^2\), где вычитания нет вовсе. Ответ автопроверки — значения при \(x = 10^{-8}\) и \(x = 10^{-5}\).

Задача 7.3. \(\sqrt{a^2 + b^2}\) без переполнения. Не только вычитание: при \(a = 3\cdot 10^{200}\) квадрат \(a^2 = 9\cdot 10^{400}\) не помещается в double и превращается в \(\infty\), при \(a = 3\cdot 10^{-200}\) — исчезает в 0. Реализуйте hypot_safe через масштабирование: \(m = \max(|a|,|b|)\), результат \(m\sqrt{(a/m)^2 + (b/m)^2}\); отдельно обработайте \(m = 0\). Ответ автопроверки — три значения.

Что унести с лабы

  1. Относительная ошибка наивной суммы \(n\) слагаемых одного знака растёт как \(n u\) (наклон 1 в log-log — измерено); при случайных знаках — как \(\sqrt n\, u\).
  2. Компенсированное суммирование Кэхэна возвращает полную машинную точность \(\sim u\) ценой ×4 арифметических операций.
  3. Попарное суммирование даёт \(u\log_2 n\) без вспомогательных переменных — потому оно и стало умолчанием в NumPy.
  4. Порядок слагаемых имеет значение: для рядов с убывающими членами суммируйте с конца.
  5. Не полагайтесь на «математическую» ассоциативность \(+\) в оптимизирующем компиляторе: -ffast-math ломает Кэхэна.
  6. Катастрофа вычитания лечится не более точной арифметикой, а переписыванием формулы: Виета для корней, половинный угол для \(1-\cos x\), масштабирование для \(\sqrt{a^2+b^2}\).
  7. Невязка — дешёвый измеритель обратной ошибки. Малое \(\kappa\) плюс большая ошибка ответа означает неустойчивый алгоритм, а не плохую задачу.
