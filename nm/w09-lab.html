Готовые решатели: Eigen

Работа выполняется на своём компьютере, а не в браузере: цель — научиться подключать готовую библиотеку и выбирать решатель по свойствам матрицы (§ 9.6). Сами решатели писать не нужно. Используется библиотека Eigen (§ 9.7); программы на C++ собираются с оптимизацией.

Сдать отчёт (PDF) с таблицами и ответами на вопросы и файлы программ .cpp — в профиле, раздел «Домашние задания», работа «Лаба 9».
Можно любые классы Eigen, стандартную библиотеку C++ (<vector>, <chrono> и т. д.), SciPy — для проверки.
Нельзя писать собственные разложения: цель работы — пользоваться библиотекой.

0. Установка и проверка

Установите Eigen 3.4 одним из способов из таблицы § 9.7 (проще всего — скачать архив с eigen.tuxfamily.org и распаковать). Нужен компилятор C++: на Windows — MSYS2 (pacman -S mingw-w64-ucrt-x86_64-gcc) или Visual Studio, на Linux и macOS — системный g++ или clang++. Соберите и запустите проверочную программу:

#include <iostream>
#include <Eigen/Dense>

int main() {
    std::cout << "Eigen " << EIGEN_WORLD_VERSION << "." << EIGEN_MAJOR_VERSION
              << "." << EIGEN_MINOR_VERSION << "\n";
    Eigen::Matrix3d A;
    A << 2, 1, 1,
         4, 3, 3,
         8, 7, 9;
    Eigen::Vector3d b(4, 10, 24);
    Eigen::Vector3d x = A.partialPivLu().solve(b);
    std::cout << "x = " << x.transpose() << "\n";   // 1 1 1
}
g++ -O2 -DNDEBUG -I путь/к/eigen-3.4.0 check.cpp -o check
./check

Программа должна вывести версию Eigen и решение \(x=(1,1,1)\). Если компилятор сообщает Eigen/Dense: No such file or directory, путь после -I указан неверно: это должна быть папка, внутри которой лежит папка Eigen. Пользователи CMake берут файл CMakeLists.txt из § 9.7.

Время во всех заданиях измеряйте так:

#include <chrono>
auto t0 = std::chrono::steady_clock::now();
/* ... измеряемый фрагмент ... */
double sec = std::chrono::duration<double>(std::chrono::steady_clock::now() - t0).count();

Задание 1. Плотные системы и ключи компиляции

Дано случайная матрица \(A\) (MatrixXd::Random(n, n)) и вектор \(b\) (VectorXd::Random(n)), \(n=500,\ 1000,\ 2000\).
Найти время решения \(Ax=b\) разными способами и проверить оценки стоимости § 9.1–9.3.
  1. Для каждого \(n\) измерьте отдельно время LU-разложения (PartialPivLU) и время одного solve по готовому разложению; время решения через A.inverse() * b; время разложения Холецкого (LLT) симметричной положительно определённой матрицы \(S=A^{\mathsf T}A+nI\). Для каждого способа вычислите относительную невязку \(\|Ax-b\|/\|b\|\).
  2. Соберите ту же программу с -O0 и с -O2 -DNDEBUG и сравните время LU при \(n=1000\).

В отчёте. Таблица времён и невязок. Во сколько раз растёт время разложения при удвоении \(n\) и согласуется ли это с оценкой \(\tfrac23n^3\)? Во сколько раз разложение дороже одного solve и почему — сравните с \(\tfrac23n^3\) и \(2n^2\). Во сколько раз LLT быстрее PartialPivLU и почему его нельзя применить к самой \(A\)? Что покажет info(), если всё же применить? Во сколько раз -O2 быстрее -O0?

Задание 2. Неявная схема: разложение один раз

Дано уравнение теплопроводности \(u_t=u_{xx}\) на \([0,1]\), \(u(0,t)=u(1,t)=0\), \(u(x,0)=\sin\pi x\); точное решение \(u=e^{-\pi^2t}\sin\pi x\). Неявная схема примера A § 9.0 с \(n\) внутренними узлами, \(h=1/(n+1)\), \(\tau=\sigma h^2\); значения \(n\) и \(\sigma\) — по варианту.
Найти решение при \(t=T=0{,}05\) (число шагов \(T/\tau\), округлённое до целого) и сравнить способы решения систем на шагах.
  1. Соберите матрицу схемы как SparseMatrix<double> из троек. Выберите решатель по таблице § 9.6 и обоснуйте выбор.
  2. Способ А: разложение один раз до цикла, в цикле только solve.
  3. Способ Б: новый объект решателя и новое разложение на каждом шаге.
  4. Способ В: та же матрица как плотная MatrixXd, PartialPivLU один раз до цикла.
  5. Для способа А найдите ошибку \(\max_i|y_i-u(x_i,T)|\). Повторите расчёт с вдвое меньшими \(h\) и \(\tau\) (то есть \(n\to2n+1\), \(\sigma\to\sigma/2\)) и оцените, во сколько раз уменьшилась ошибка.

В отчёте. Таблица: число шагов, время способов А, Б, В, ошибка. Объясните, почему А быстрее Б и почему В медленнее А, хотя разложение в обоих выполнено один раз (сравните число операций одного solve для трёхдиагональной и плотной матрицы). Сколько памяти занимала бы плотная матрица при \(n=10^5\)? Какой порядок точности по \(h\) показывает опыт с уменьшением шагов и согласуется ли он со схемой (порядок \(\tau+h^2\))?

Задание 3. Двумерная задача: заполнение и переупорядочение

Дано уравнение Пуассона \(-\Delta u=f\) в квадрате \([0,1]^2\), \(u=0\) на границе; точное решение \(u=\sin(a\pi x)\sin(b\pi y)\), \(f=(a^2+b^2)\pi^2u\); \(a\), \(b\) — по варианту. Пятиточечная схема на сетке \(m\times m\) внутренних узлов, \(h=1/(m+1)\), номер узла \(k=i\cdot m+j\).
Найти решение для \(m=50,\ 100,\ 200,\ 400\) и сравнить решатели.
  1. Соберите матрицу из троек (в строке узла: \(4/h^2\) на диагонали, \(-1/h^2\) для каждого из соседей, лежащих внутри квадрата).
  2. Решите систему тремя решателями: SimplicialLLT<SparseMatrix<double>, Lower, NaturalOrdering<int>> (без переупорядочения), SimplicialLLT<SparseMatrix<double>> (по умолчанию — переупорядочение AMD) и SparseLU<SparseMatrix<double>>.
  3. Для двух вариантов Холецкого выведите число ненулевых элементов множителя: SparseMatrix<double>(solver.matrixL()).nonZeros().
  4. Для каждого \(m\) вычислите относительную невязку и ошибку \(\max_k|y_k-u_k|\).

В отчёте. Таблица: \(m\), \(n\), число ненулевых в \(A\), в \(L\) без переупорядочения и с ним, время трёх решателей, невязка, ошибка. Как растёт число ненулевых в \(L\) без переупорядочения при удвоении \(m\) и почему (рис. 12 § 9.4)? Во сколько раз переупорядочение уменьшает время при \(m=400\)? Почему SimplicialLLT быстрее SparseLU для этой матрицы? Невязка мала при всех \(m\) — значит ли это, что ошибка тоже мала? От чего зависит ошибка при больших \(m\)?
